# Part 0. 이 문서를 쓰는 이유

대시보드는 숫자를 **보여주기만** 한다. 이 데이터에는 **모르면 반드시 오독하는 구조적 함정이 7개 이상** 있다.

# Part 1. 데이터 구조

## 1-1. 3개 소스의 성격이 다르다

| 소스 | 단위 | 성격 |
|---|---|---|
| **실적** (사업계획 통합관리 파일, 매출 301+원가 299행) | **천원** | 시스템의 **현재 최신 상태** |
| **재무** (PPT 추출, 239행) | **원** | 보고 시점마다 찍힌 **스냅샷 누적** — 제안·착수·중간·완료가 각각 별도 행 |
| **KPI** (PPT 추출, 208행) | 항목별 상이 | 같은 PPT의 KPI 표 |

→ **재무 매출을 단순 합계하면 같은 프로젝트를 3~4번 센다**(재무 644억 vs 실적 연간 추정 366.5억). 둘을 나란히 비교하는 것 자체가 오류.

## 1-2. 실적의 매출행/원가행 2행 구조
프로젝트 1건 = 매출행 + 원가행. 손익 값(BA~BG)은 **매출행에만**(원가행은 전부 0). 매출행 BB(직접원가) = 원가행 BH(연간추정)가 두 행을 잇는 고리. 집계는 매출행만(코드가 이미 그렇게 함).

## 1-3. '원가'의 두 가지 뜻 ★
- 원가행의 '원가' = KPI 카드의 '원가' = **직접원가만**(244.4억)
- 손익의 총원가 = 직접원가 + 인건비 + 공통원가 + 관리비 = **362.2억(1.48배)**
→ "매출 376.5 − 원가 244.4 = 132.0"은 경상손익(14.3억)이 아니라 **매출이익**. 가장 흔한 오독.

## 1-4. AR열 함정 (코드로 보정 중)
AR열 이름은 '8월 결산 기준 실적 집계'지만 실제 값은 **1~12월 전체(미래 추정 포함)**. 그대로 쓰면 누계가 2.6배(개별 최대 30배). `performance.py`가 1~기준월만 재합산. 원본 엑셀을 직접 볼 때 주의.

# Part 2. 대시보드 읽는 순서 — 5단계

## 0단계 — 믿어도 되나 (30초)
1. 네브바 빨간 "!" 배지 확인 — 뜨면 KPI↔재무 코드 불일치/충돌. 해당 파일 파트의 숫자는 판단 보류.
2. 최신화 시각 확인 — 실적은 매달 갱신(초=전월 추정, 중순=전월 확정). 월초 숫자는 **추정치**.

## 1단계 — 전사 착지 전망 (1분): 3개를 세트로
| 지표 | 값 |
|---|---|
| 계획 | 321.3억 |
| 누계(1~8월) | 145.2억 |
| 연간 추정 | 366.5억 |

단순 달성률 45.2% / **안분 달성률** 145.2 ÷ (321.3×8/12) = **67.8%**(진짜 페이스) / **연간 전망률** 114.1%(착지).
**규칙**: 달성률은 항상 기준선 `경과월/12`(8월 66.7%, 9월 75.0%, 10월 83.3%)과 함께 말한다.
FP&A 표준과 같다 — 기간 중 실적을 연간 목표와 직접 비교하지 말고 ① YTD÷연간계획 ② 기대 페이스(계획×경과비율) ③ ②대비 차이를 본다. 일시적(타이밍) 편차와 구조적 편차를 구분(구조적만 전망 수정 사유).

# Part 6. AI 분석 프롬프트 — 경영실적/재무데이터 탭

> 메모(2026-09-17): 표보다 **서술**이 더 잘 읽힌다는 피드백. 표는 비교용 보조로만, 어조는 "몰아치기·최악·위기"·신호등 이모지 없이 차분하게. 실제 반영은 `ai_insight.py`.
> 숫자는 Python이 계산해 넘기고 LLM은 해석만(Part 8).

```markdown
당신은 현대차그룹 기술교육 조직의 경영관리 애널리스트입니다.
아래 실적 데이터를 읽고, 팀장·경영진이 5분 안에 의사결정할 수 있는 분석문을 작성하세요.

## 반드시 지킬 해석 규칙 (위반 시 분석 전체가 무효)
1. 달성률은 단독으로 말하지 말 것. 항상 `누계 / 안분기대치(계획×경과월/12) / 연간추정` 3개와 기준선("8월 기준선 66.7%")을 함께.
2. '원가'는 두 가지. 원가행의 원가 = 직접원가만. 총원가 = 직접+인건비+공통+관리비(약 1.48배). `매출−직접원가`는 매출이익이지 경상손익이 아니다.
3. 손익률·원가율은 금액 가중평균(Σ손익÷Σ매출). 단순평균 금지.
4. 재무 데이터와 실적 데이터를 직접 비교하지 말 것(재무=단계별 스냅샷 누적, 실적=현재 상태).
5. 계획 0 프로젝트는 달성률에서 제외하고 "계획 미수립 N건/N억"으로 별도 보고.
6. 패스스루(직접원가 비중 85%↑)는 매출 성장 근거로 쓰지 말고 별도 표기.

## 분석 구조
① 한 줄 결론(연말 착지 전망 + 최대 리스크, 숫자 포함)
② 착지 전망(계획/누계/안분기대치/연간추정, 안분 달성률로 페이스 판정: 100%↑ 선행·90~100 정상·90 미만 지연)
③ 페이스 리스크(파트별 잔여 필요액/월 필요/기존 월평균/필요배수, 2배 초과는 굵게 + 전사 잔여 비중)
④ 수익성 진단(손익률/원가율/직접원가 비중. 원가율 100% 초과 = "하면 할수록 손해", 최고 수익 파트의 구조적 이유)
⑤ 무엇이 돈이 되는가(교육형태·사업구분 손익률 상·하위 3, "규모×수익성" 2축으로 재배분 방향)
⑥ 즉시 조치 건(5개 이내, 금액 영향 순): `[대상] 사실(숫자) → 원인 추정 → 권고 액션 → 예상 영향(억)`. 적자는 건수가 아니라 적자 매출 N억(N%)으로. 같은 유형·고객군 동시 적자는 단가 구조 문제로 묶어서
⑦ 데이터 신뢰도 경고(해당 시): 코드 불일치/충돌(충돌 = 한쪽 데이터가 덮어써져 사라짐 → 해당 파트 집계 신뢰 불가), placeholder 비중, 사유 미기재 건수, 데이터 기준일과 추출 시각 구분. 없으면 "데이터 이상 없음"

## 서술 규칙
- 모든 발견은 `무슨 일 → 왜 중요 → 누가 영향 → 무엇을 해야`. 숫자 재진술은 분석이 아니다
- 비교 기준 없는 숫자 금지(목표·전기·벤치마크 중 하나). 주어진 집계값을 새로 계산하지 말고 해석만("계산 필요: X"로 표시)
- 단일 시점 이상치는 단정 가능, 추세·계절성·구조 변화는 불확실성 명시. 모호한 헤지 대신 "확인 필요: X가 Y인지"로 대상 특정
- 이상치는 `대상|유형|사실|심각도(금액 기준)|영향범위|권고`, 권고는 예상 효과 순
- 경영진용 900자 이내(표 제외), 섹션당 3~4문장
```

근거: 자동 분석의 가치는 원인·중요도·다음 행동에 있고(Narrative BI), 숫자는 결정론적으로 계산하고 LLM은 표현만 맡겨야 환각이 준다. 신선도는 작업 시각이 아니라 **데이터 기준일**로 표기.

# Part 7. AI 분석 프롬프트 — KPI/경영현황 탭

```markdown
당신은 현대차그룹 기술교육 조직의 KPI 관리 애널리스트입니다.

## ⚠️ 먼저 판정할 것 — 입력 완성도가 낮아 집계값을 그대로 신뢰할 수 없다
1. 항목별 목표 기재율 = 목표값이 숫자인 행 ÷ 전체 행. 50% 미만이면 "목표 미수립"으로 보고 달성률 계산 금지
   (2026-09 실측: NPS 169/208, 전략기술과정 36, 특화교육체계 31, AI교육_고객사 23, 신사업_신규기존건수 7)
2. 실적 0 비율 — "0 입력"과 "미입력"을 구분. 합계 0은 "실적 없음"이 아니라 "미집계"일 수 있음 → 확인 대상으로 제시
3. 프로젝트당 보고단계 중복 — 집계는 가장 진행된 단계 1건만(완료>중간>착수>제안). 중복 코드는 서로 다른 프로젝트의 코드 공유 오입력일 수 있음

## 분석 구조
① 데이터 신뢰도 판정(필수, 맨 먼저): `KPI 항목|목표 기재율|실적 기재율|판정` — 둘 다 70%↑ [분석가능] / 한쪽만 [참고용] / 둘 다 50%↓ [집계불가]. 집계불가가 있으면 맨 위에 "8개 KPI 중 N개는 목표 기재율이 부족해 달성률 산출이 어렵습니다" 안내
② 분석 가능 항목 실적 진단: 목표/실적/달성률/전년 유사실적, 안분 기준선 병기, 0~5 척도는 소수 1자리·10 초과는 오입력 의심 플래그
③ 파트별 KPI 기여도([분석가능]만): 기재 안 된 파트는 0이 아니라 "미기재"
④ 목표 현실성: 달성률 10% 미만은 부진이 아니라 목표 설정 오류 가능성 제시(예: 전략기술과정 목표 56 vs 실적 5)
⑤ 입력 품질 개선 요청: 파트별 미기재 항목 수/확인 필요 행 수, 담당 파트 명시
⑥ 코드 충돌 경고: 충돌 코드·파일 목록 + "이 파일들의 KPI는 집계에서 누락됐을 수 있음"

## 서술 규칙
- 미입력을 실적 0으로 단정 금지("미기재"/"0 입력" 구분)
- 기재율 낮은 항목은 순위·비교·추세를 말하지 말 것(분석을 안 하는 것이 맞다)
- 숫자 없는 문장·모호한 헤지 금지, 4단계 서술은 Part 6과 동일, 전체 700자 이내
```

# Part 8. 구현 메모

파이프라인: PPT 추출 → 엑셀 갱신 + 코드충돌 시트 → **집계 지표 계산(Python, 결정론적)** → LLM 호출(프롬프트 + 이 문서 + 집계 지표) → 분석문 저장·노출.
**숫자는 Python, LLM은 해석·표현만.** 미리 계산해 넘길 값: 계획/누계/안분기대치/연간추정, 파트별 필요배수, 적자 매출 가중 비율, 교육형태·사업구분별 손익률, 전월 델타, 코드충돌·불일치 건수.

- **전월 스냅샷(미구현)**: 추출 때마다 주요 지표를 `data/snapshots/YYYY-MM.json`으로 남기면 "신사업 손익률 −0.5%(전월 대비 −1.2%p)" 같은 MoM 서술이 가능 — AI 분석 가치를 가장 올리는 한 가지.
- **검수 루프**: LLM 출력은 초안. 원인 설명이 데이터로 뒷받침되는가("~때문에"), 추세 단정이 없는가, 권고가 실행 가능한가, 충실성(표 데이터 일치)과 유창성을 분리 확인.

# Part 10. 환각 방지 보강 후보 (2026-09-18 조사, `ai_insight.py` 반영 여부는 별도 판단)

1. **"모른다고 말할 권한" 한 문장 추가**(Anthropic 가이드) — 비용 없음, 최우선.
2. **재무/실적 탭에 표본 크기 규칙**: 파트 건수 < 5(예: K뉴딜TF 3건)면 순위·추세·벤치마크 비교 없이 개별 사실만(건수 병기) — Part 7의 "기재율 낮은 항목은 순위·추세 금지"와 같은 논리.
3. **"최종 점검" 섹션**(출력 전 사용 숫자가 전달 데이터에 있는지 재확인) — 단일 호출 내 자기검증, 진짜 CoVe보다 약하지만 추가 호출 없음.
4. 외부 지식 사용 제한: 원인 추정에 학습된 일반 지식을 섞지 말고 전달된 데이터 안에서만 근거를 찾게(특히 Part 6 ⑥).
5. 숫자 뒤에 원본 키를 소괄호로 표기하는 방식 — 최종 출력이 지저분해지고 서술 선호와 충돌 가능, A/B 후 결정.
6. 진짜 2차 호출 CoVe는 지연 2배(탭당 15~30초)라 보류 — "다시 분석" 버튼 전용으로만 나중에 검토.
