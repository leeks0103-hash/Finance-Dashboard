# 알려진 문제 코드

## [2026-07-20] profit_rate 파싱 이중 처리
- **위치**: `app.py` 37~45줄
- **문제**: `safe_num()` 함수가 이미 `%` 제거를 처리하는데, `profit_rate`만 별도 파싱 로직을 중복 작성
- **해결**: `safe_num(r[10])`으로 통일하면 됨
- **상태**: 기능상 문제 없음. 리팩토링 시 통합

## [2026-07-20] EXCEL_PATH 하드코딩
- **위치**: `app.py` 8~13줄
- **문제**: 로컬 전용 절대경로 하드코딩 — 다른 PC에서 동작 불가
- **해결**: 다른 환경에서 사용 시 해당 줄 직접 수정 필요. `.env`는 만들지 않음(보안 이슈 아님)
- **상태**: 단일 PC 운영 중이므로 현재는 유지
